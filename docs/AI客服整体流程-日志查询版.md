## 分步文字说明（与原图逐一核对版）

### STEP 0 · 入口


| 节点               | 说明                                                                     |
| ------------------ | ------------------------------------------------------------------------ |
| **玩家反馈的消息** | 整个流程起点。玩家通过客服渠道提交反馈消息，可能包含文字、截图等多种形式 |

---

### STEP 1 · 初步解析（四路并行）

玩家消息进入后，同时启动以下四个处理模块：

#### 1.1 话题处理链（串行）


| 节点           | 功能                             | 详细内容               |
| -------------- | -------------------------------- | ---------------------- |
| **话题总结AI** | 将玩家的消息根据不同话题进行拆分 | 输出话题和总结         |
| **话题更新AI** | 将玩家的新消息与已有老话题做匹配 | 匹配成功 → 更新老话题 |

> 标注：**话题+总结**

#### 1.2 关键信息提取 ceshissdasd


| 节点               | 功能               | 提取项                                                                      |
| ------------------ | ------------------ | --------------------------------------------------------------------------- |
| **关键信息提取AI** | 当消息无规律时触发 | 1. 玩家反馈的话题总结<br />2. 选择出的点击事件<br />3. 分析出的问题发生时间 |

#### 1.3 图片识别


| 节点                         | 功能                                            | 子项                                                   |
| ---------------------------- | ----------------------------------------------- | ------------------------------------------------------ |

### A. 需要查日志的类型范围

> **需要查日志的应该就是：充值类，bug 类，账号类，投诉玩家类**
>
> 考虑**提示词通用性**，这些反馈类型的提示词用**参数替换**

### B. Bug 类反馈的处理说明

> **Bug 类反馈，查询日志之后如何定位问题？**
>
> bug 类反馈的日志存在推理，**反值情况**，不同问题有不同复杂度。
> **大数据领域需要**上导看，现有流程是需要客服人员测试了之后才报给项目组

### C. 账号类反馈的处理

> **账号类的反馈大多数是找账号**
>
> 怎么记的密码，怎么忘记 Pc 密码，基本最后都会去**找账号**；
> 主要还充错记录...
>
> 我需要知道：**账号/类型问题小分类下，分别需要翻哪些日志**，
> 每个日志的字段是什么意思，小分类中的问题下，**日志有什么表现**

### D. 投现/作弊玩家处理

> **投现玩家**（投诉玩家作弊，战力异常，积分异常等等）：一些能够被玩家举证的**战力基本查不到**
>
> **我需要知道：**
>
> 1. 通过玩家提供的信息（服务器、昵称、可能需要图片识别），
>    去**获取另一个玩家的 UID 并查看充值情况**，在这种情况下，
>    **那些值日志**的**字段会有**？如果被举报，如被收钱玩家是否有异常？
>    充值日志会**有什么体现**，如果有异常界，充值日志又会有**什么体现**？
> 2. **其他**投诉玩家类的反馈需要查什么**日志**，也需要**后续提供**

### E. 校验配置节点的思考

> **关于添加校验配置节点的问题**（日志被查询日志未**不包含完配置度**，
> 但是**些问又需要看者配置度**能否**定位**问题）：
>
> 1. 那些**分类**需要**查完配置度表**？
> 2. 查询配置作为**辅助定位问题的依据**，AI 如何知道**什么时候该查日志表**，
>    什么时**候不用查配置日志表**？
> 3. 查询到的**认证的**使用？通过**什么参照物对比**，
>    才能发现**玩家反馈的问题确实具有真识**？

### F. 充值值定位问题提示词理念的思考（置信度机制）

> **（充值值）定位问题提示词理念的思考（要不要引入上一步的自信度机制作为参考？）：**
>
> **0.** 玩家的**问题描述只是确定查询日志的方向**，
> 最终**确认问题需要日志结果**输入，输入为**日志判断提示词**的**输出**和玩家**问题描述**，
> **确定最终问题**，**自信度 <70% 重查**；
>
> **1.** 自信度 **>70%**，确认最终**问题**；
>
> **2.** 日志判断提示词的**结果**如果**玩家问题描述没有出入**的，
> 通过**日志判断提示词的自信度去进行判断**，自信度 **>70%**，
> 告诉**玩家没有查到所描述的问题**。
> **自信度 <70%**，**重查**；
>
> **3.** **第二次查询**如果**自信度 >70%**，
> 告诉**玩家没有查到所描述的问题**。
> **自信度 < 70%**，**邮件通知人工**，
> 并且**回复玩家将尽快解决**。

> **我需要知道**：后续哪些**先查完日志**进行改版，
> 并判断每一个**字段的意愿**，
> **UID 和订单号拿到了的情况下**，
> **充值不能提现**、**充值错服**、**分别的依据是什么**？

### STEP 1 · 初步解析（四路并行）

玩家消息进入后，同时启动以下四个处理模块：

#### 1.1 话题处理链（串行）


| 节点           | 功能                             | 详细内容               |
| -------------- | -------------------------------- | ---------------------- |
| **话题总结AI** | 将玩家的消息根据不同话题进行拆分 | 输出话题和总结         |
| **话题更新AI** | 将玩家的新消息与已有老话题做匹配 | 匹配成功 → 更新老话题 |

> 标注：**话题+总结**

#### 1.2 关键信息提取


| 节点               | 功能               | 提取项                                                          |
| ------------------ | ------------------ | --------------------------------------------------------------- |
| **关键信息提取AI** | 当消息无规律时触发 | 1. 玩家反馈的话题总结2. 选择出的点击事件3. 分析出的问题发生时间 |

#### 1.3 图片识别


| 节点                         | 功能                                            | 子项                                                   |
| ---------------------------- | ----------------------------------------------- | ------------------------------------------------------ |
| **图片识别AI（提示词如有）** | 如有图片则触发，提取并整理游戏截图/图片中的信息 | • 图片分析结果• 图像中的提示语• UID 信息• 其他信息 |

#### 1.4 模拟UID（⚠️ 原版遗漏节点）


| 节点            | 功能                                                                                | 分支                                                                                                          |
| --------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **模拟UID的AI** | 将玩家的消息根据不同话题进行拆分分析，输出提取结构化信息；同时调取/更新话题匹配逻辑 | • 不能获得到 UID →**询问 UID 流程**• 能获取到 UID → **将 UID 与反馈做关联**（获取到 ID 后可进入自查流程） |
